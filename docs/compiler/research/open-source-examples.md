# Open-source CODESYS example candidates

Research date: 2026-10-09. Primary repositories, their actual license files, and their PLCopen exports were inspected as data. No downloaded PLC code was executed, and this research does not claim vendor compilation.

## Recommendation

Port the complete authored PLC logic of **traffic control**, **mixing tank**, and **garden controller**, in that order. Together their exports contain 13 POUs, 16 actions, eight DUTs, four GVLs, and 1,559 ST body lines. This includes their simulators, not just an extracted controller or a hand-written substitute. They provide different useful cases: integer geometry/sequencing, timer-driven device models and bounded REAL updates, and fixed-array watering routes with byte colors.

The larger home-automation and MQTT projects are genuine CODESYS sources, but their interfaces, memory operations, transports, callbacks, and vendor dependencies exceed the current finite/static PLC-TS language. A stub transport or a small extracted function would not constitute a complete port.

## Larger unit-test corpus

[UniTest](https://github.com/tkucic/UniTest/tree/7d8bbb1752acd975e944f1219deff2541835ed3a) is another genuine, MIT-licensed CODESYS corpus. Its pinned `UniTest_codesys/UniTest.xml` contains 333 POUs (165 functions, two FBs and 166 programs), 748 actions, four DUTs and one GVL. The 1,081 ST body/action fragments total 11,577 decoded lines, including comments and blanks; 10,888 are test programs/actions. The [author README](https://github.com/tkucic/UniTest/blob/7d8bbb1752acd975e944f1219deff2541835ed3a/README.md) explains that its assertion tests were generated by a script. Its size mostly reflects a repetitive test matrix rather than 11,000 lines of application control logic.

The complete source is not admitted by the current static PLC-TS language: it contains 101 pointer declarations across 26 POUs, ADR/SIZEOF operations, runtime-sized loops, long time/calendar domains, dynamic REAL reporting and runtime-indexed results. Straight translation of 333 POUs plus action helpers would also exceed the specialization limit. The application export includes 14 visualization library references/placeholders and a separate visualization task; its 20 ms test task has 167 calls to 166 programs because `test_assertTrue` is called twice. This is a useful future compiler corpus, but an extracted subset or stub reporter would not qualify as a full working port. No copy of this unsupported port is presented as a working example.

## Exact selected scope and prerequisites

The primary [traffic XML](https://github.com/tkucic/plc_traffic_control/blob/49c9de4e8ce588de3fd7f831e5f78ce6e303c1d9/plc_traffic_control.xml) defines a 5 ms, priority-1 task calling **main then simulator**. The authored external calls are TON, Util.BLINK, TIME_TO_UDINT and UDINT_TO_UINT. Preserve the STRING(255) fault messages. The TIME subtraction before conversion represents a countdown in milliseconds; conversion and division must preserve integer truncation. There are no REAL declarations in this export.

The primary [mixing XML](https://github.com/tkucic/plc_hello_mixing_tank/blob/17e0213b1c7c46fd44ff7d9a52a6bb9e500d65de/plc_hello_mixing_tank.xml) defines a 20 ms, priority-1 task calling **main then simulator**. Its external calls are TON, BOOL_TO_REAL and LIMIT. Tank level starts at 25 and receives +0.1 per opened fill valve and -0.2 for an opened drain, followed by LIMIT(0, level, 100). Simulator rotation advances by 1, and HMI rotation by 2, when the respective motor feedback is true; each resets at 360. Keep those REAL constants, operation order and rounding. Device inputs have defaults and some TON reset calls omit PT, so the port must supply preserved values explicitly through its complete update schema.

The primary [garden XML](https://github.com/tkucic/plc_garden_controller/blob/ef3e937c8ead73a7078925b0da32fca59c85379b/plc_garden_controller.xml) defines a 20 ms, priority-1 task calling **main then simu**. External calls are TON, R_TRIG, Util.BLINK, ABS, MAX, LIMIT and BOOL_TO_REAL/BYTE/UINT. Four instruction tables use ARRAY[0..24,0..1] OF INT; retain all 50 coordinates of each table using nested fixed arrays. Each simulator garden contains 25 Flower records. The pulse frequency input is 20 ms; humidity decreases by 0.07 on a pulse and increases by 4 while watered. Red/green updates occur in BYTE storage before LIMIT(1, channel, 254), so replacing wrap with saturation would change the authored behavior. BYTES_TO_DWORD packs B0 into bits 0..7 through B3 into bits 24..31. Watering index i advances then resets at 25; the static port needs a proved index without changing valid-state sequencing.

Standard and Util provide the selected runtime FBs. The upstream projects also carry generated visualization/device libraries and VISU_TASK calls. Preserve the native project/export/visualization assets as upstream material and account for them separately from generated PLC-TS logic. A compatible engineering template and explicit task plan are required; substituting generic hardware settings does not verify the original hardware setup.

## Other primary sources screened

- **OSCAT:** the [official archived repository](https://github.com/eclipse-oscat/oscat-libs-archive) explicitly excludes its legacy artifacts from EPL-2.0 and says their original library-specific agreements apply. The [CODESYS store](https://store.codesys.com/en/catalogsearch/result/index/?cat=4&q=oscat) confirms actual CODESYS 3 ports. A generic Eclipse organization license badge is insufficient evidence for redistributing a selected legacy library. The archive's broad math/string/network scope also exceeds this complete-port task.
- **CODESYS Forge:** its [primary library catalog](https://www.forge.codesys.com/lib/wiki/Home/) supplies a useful CODESYS-specific discovery list, but each project's source/license must be checked individually; catalog-level availability is not the selected artifact's license.
- **WAGO:** [official repository discovery](https://github.com/orgs/WAGO/repositories) and [firmware SDK material](https://github.com/WAGO/pfc-firmware-sdk-G2) were screened. The more directly useful readable application source was the MIT home-automation project above, whose WAGO library dependencies and redistribution exclusions are explicit.
- **TwinCAT-only distinction:** [FB_CaseStateMachine](https://github.com/FellowWithLaptop/FB_CaseStateMachine) says its example was created with TwinCAT and uses the TwinCAT Eventlogger; stating that the concept is possible in CODESYS does not establish an actual CODESYS project. It was not selected.

Local inspection evidence is in the task's `work/open-source-research/` folder: pinned GitHub metadata, original XML/README/LICENSE files, generated source documentation, and JSON source inventories. No imported repository instructions were followed or code run during inspection.
