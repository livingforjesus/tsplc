# Frame-assembly source port

This manifest maps the supplied PLC project's 42 Structured Text files and nine ancillary files to this example. Source SHA-256 values record the captured pre-port baseline of `/Users/Apple/.t3/worktrees/rip-technologies/t3code-bd440e47/apps/frame-assembly/plc`; port hashes describe the current example. The template and its `.gitattributes` file are exact byte copies of that baseline.

The pre-port inventory contains no PLC-root `.gitignore`; this port adds one to exclude its own generated `.vplc/` outputs, dependencies, and engineering sidecars. Ignored build applications, IDE caches, `.turbo` logs, runtime data, and `node_modules` are outside the authored inventory and were not copied.

## Control and interface preservation

- Main retains the scan order: PRG_ConveyorSetup, PRG_LineScanners, PRG_Diverters.
- All original GVL names, exported storage identifiers, record field names, and numeric enum values remain present. The target configuration preserves the five GVL namespaces and the Main PROGRAM name. LineIO, LineStations, LineCollections, and LineScannerRequests retain their original linkalways/readwrite symbol publication; LineConstants remains an internal constant list.
- Cards remain FixedArray<ST_LineCS1001, 256, 1>. ResultData and request Barcode contain 484 bytes; UserData contains 492 bytes. Routing Barcode remains STRING<80>.
- The original structure defaults Collection.Full=true and Station.Capacity=2 are explicit at every authored global allocation. The remaining structure fields use their original zero/false/empty defaults. Interfaces describe the complete value layout; they do not add JavaScript runtime constructors.
- All four FBs are static FunctionBlock allocations. Persistent private state remains private fields; execute locals reset per invocation. Shared device/request records are InOut borrows, and whole-record/array assignments use explicit copy.
- The lift's three-second input default is supplied explicitly at its sole call site. Request rearming, overload qualification, wrong-direction fault expressions, timeout latching, and actual motor feedback remain unchanged.
- Scanner reply application, byte copying, result-length limits, acknowledgement order, pass-through barcode publication, and route-ready locking preserve the authored handshake. Diverter selection remains locked until departure. Finishing starts at Left and its first photoeye arrival selects Through.
- The transport FB preserves the original private CardIndex field. The for header uses CardIndex directly; the compiler proves one-based array access and preserves CardIndex at 257 after the inclusive 1..256 loop.

## Build scope

`vplc.config.ts` replaces the original engineering configuration. It selects MainTask at 20 ms/priority 1, the copied virtual template, the original removeObjects list, symbol export and the Docker compiler image. PLC tsconfig includes only src/**/*.ts; the host configuration has a separate tsconfig.host.json. The vPLC CLI checks the TypeScript, emits Structured Text through `@vplc/compiler`, and compiles it through `@vplc/build` in Docker. These check/build commands do not execute the PLC TypeScript or deploy/start hardware or a runtime. PORT.md, README.md, tsconfig.host.json, and the new .gitignore are port-owned supplementary files.

Original wiring and commissioning notes are retained in src/README.md, src/lifts/README.md, and templates/README.md. References to the source application's bridge/simulation describe systems outside this PLC-only example. Checking, emitting, or compiling this virtual project does not establish a commissioned machine. Electrical/fieldbus mappings, lift endpoint assumptions and time margins, and occupancy coverage remain the original unresolved installation items.
